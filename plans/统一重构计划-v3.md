## 2. Phase 1: AI 助手核心修复 + 统一命令接口

### 目标

2. 提供统一的 `sendCommand()` 接口供所有组件使用

### 2.1 重写 `processWithAI` — 恢复多轮循环（修复 B4）

**文件**：`src/renderer/shared/services/AIAssistantService.ts`

**当前问题**：单次 AI 调用，无法完成"先读后写"的复合操作。

**改动**：改为 while 循环（最多 5 轮）：

```
processWithAI(text, model):
    iterations = 0, MAX = 5
    accumulatedContent = ""
    actionResults = ""
    
    while iterations < MAX:
        iterations++
        
        构建当前轮 prompt
        调用 AI（流式输出）
        解析响应 → toolCalls + textParts
        
        if toolCalls 非空:
            → handleToolCalls（见 2.2）
            → 根据结果决定 continue / break / return
        elif 有创建意图 AND 文字够长:
            → 自纠错 或 handleSmartExtraction
            → return
        else:
            → 普通问答 → break
    
    显示最终结果
```

### 2.2 完善 `handleToolCalls` — 修复 B2

**关键修复**：nonFileOps（read_folder/search/batch_read）执行后**必须 continue**，让 AI 看到结果再决定下一步。

```
handleToolCalls(toolCalls, textParts, originalText, model):
    分类：fileOps / nonFileOps
    
    显示 textParts
    
    for each nonFileOp:
        if ask_input / ask_choice / plan:
            → 弹出交互提示 → return（等用户）
        else:
            → 执行操作 → 收集结果
    
    if fileOps 非空:
        → 弹确认框 → 用户确认/取消
    
    if nonFileOps 非空 AND 无 fileOps AND 无 needsUserInput:
        → 将工具结果注入下一轮 prompt
        → continue ✅
    
    → COMPLETED
```

### 2.3 激活自纠错机制 — 修复 B1/B5

在循环中，当 AI 输出纯文字但用户意图是创建内容时：

```
if toolCalls 为空 AND detectCreateIntent(text) AND textParts.length > 50:
    if selfCorrectionAttempts < 2:
        → 注入 getSelfCorrectionPrompt(attempt)
        → continue
    else:
        → handleSmartExtraction（兜底）
        → return
```

### 2.4 新增 `sendCommand` 公共方法

```typescript
/**
 * 统一的 AI 命令入口——所有"AI 生成"按钮都走这里
 */
async sendCommand(command: string, model: ModelConfig, options?: {
  silent?: boolean;
  label?: string;
}): Promise<void> {
  if (!options?.silent) {
    this.addMessage({ role: 'user', content: command });
  }
  
  this.state.isProcessing = true;
  this.updateAgentState({
    phase: AgentPhase.ANALYZING,
    currentTask: options?.label || this.summarizeTask(command),
    progress: 10,
    requiredAction: 'none',
    error: null,
    pendingFiles: [],
    iteration: 0,
  });
  this.emit();
  
  try {
    await this.processWithAI(command, model);
  } catch (err) {
    this.addMessage({ role: 'assistant', content: `❌ 执行出错：${err instanceof Error ? err.message : '未知错误'}` });
  } finally {
    this.state.isProcessing = false;
    this.emit();
  }
}
```

## 6. Roo-Code 设计模式借鉴

> 写小说和写代码本质相同：都需要在长篇内容中保持上下文一致性、逻辑连贯性、合理的结构组织。
> 以下是从 Roo-Code（Apache 2.0 开源）中提炼的可直接应用于小说项目的设计模式。

### 6.1 Agent 循环模式（核心借鉴）

**Roo-Code 实现**（[Task.ts:L2472-L2498](file:///d:/Users/qq274/Desktop/开发文件/ai小说项目开发/墨渊灵笔/参考项目/Roo-Code-main/src/core/task/Task.ts#L2472-L2498)）：

```
initiateTaskLoop(userContent):
    while (!abort):
        didEndLoop = recursivelyMakeClineRequests(userContent)
        if didEndLoop: break
        else: userContent = "请继续完成任务"
```

**小说项目应用**：这正是 Phase 1 中 `processWithAI` 的 while 循环设计。关键点：
- 每次循环给 AI 上一次工具执行的结果
- AI 看到结果后决定下一步（继续操作 or 完成任务）
- 有最大迭代次数防止死循环
- 用户可随时中止

### 6.2 状态机模式

**Roo-Code 实现**（[agent-state.ts](file:///d:/Users/qq274/Desktop/开发文件/ai小说项目开发/墨渊灵笔/参考项目/Roo-Code-main/apps/cli/src/agent/agent-state.ts)）：

```
NO_TASK → RUNNING → STREAMING → WAITING_FOR_INPUT → IDLE
                                      ↘ RESUMABLE
```

**小说项目应用**：当前 `AgentPhase` 已有基础状态，建议增强为：

```
IDLE → ANALYZING → GENERATING → VALIDATING → WAITING_CONFIRM → EXECUTING → COMPLETED
  ↑         ↓            ↓            ↓              ↓              ↓          ↓
  └─────────┴────────────┴────────────┴──────────────┴──────────────┴── ERROR ─┘
```

每个状态对应明确的 UI 表现和用户可执行的操作，避免"卡在 85% 等待确认"的问题。

### 6.3 上下文窗口管理模式

**Roo-Code 实现**（[context-management/index.ts](file:///d:/Users/qq274/Desktop/开发文件/ai小说项目开发/墨渊灵笔/参考项目/Roo-Code-main/src/core/context-management/index.ts)）：

```
1. 计算当前 token 使用量
2. 判断是否超过阈值（默认 contextWindow 的 90%）
3. 超过 → 先尝试智能摘要（condense）
4. 摘要失败 → 滑动窗口截断（truncate）
5. 保留关键上下文（command blocks、environment details）
```

**小说项目应用**：当前 `buildCompressedHistory` 只是简单截断，建议升级为：

```
manageNovelContext(messages, contextWindow):
    totalTokens = estimateTokens(systemPrompt + messages + fileContext)
    
    if totalTokens > contextWindow * 0.85:
        // 第一层：智能摘要
        summary = summarizePriorMessages(oldMessages)
        // 保留最近的 N 条消息 + 摘要
        messages = [summaryMessage, ...recentMessages]
        
        if stillTooLarge(messages):
            // 第二层：正典优先截断
            // 正典内容（⭐标记文件）永远保留
            // 非正典引用可以被截断
            messages = truncateNonCanonContent(messages)
    
    return messages
```

### 6.7 错误恢复与退避模式

**Roo-Code 实现**：
- `consecutiveMistakeCount`：连续错误计数
- `consecutiveMistakeLimit`：达到上限后询问用户
- 指数退避重试（最多 10 分钟）
- 上下文窗口错误自动减少上下文后重试（最多 3 次）

**小说项目应用**：当前 Phase 1 的自纠错机制可以进一步增强：

```typescript
handleAIError(error, attempt):
    if isContextWindowError:
        // 自动压缩上下文后重试
        compressedContext = compressContext(0.75) // 保留 75%
        retry with compressedContext
    
    if isRateLimitError:
        // 指数退避
        await delay(Math.min(1000 * 2^attempt, 60000))
        retry
    
    if consecutiveMistakeCount >= limit:
        // 询问用户是否继续
        showPrompt("AI 连续多次未能正确完成任务，是否继续？")
```
