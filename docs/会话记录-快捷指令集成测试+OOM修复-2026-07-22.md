### 3. 发现真实生产 Bug

集成测试运行时触发 V8 heap OOM：
```
FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memory
```

**根因分析**：
- [useChatInput.ts](file:///d:/Office%20software/Development%20Project/moyuan-lingbi/src/renderer/app/app-shell/ai-assistant/hooks/useChatInput.ts) 的 `useEffect` 依赖 `[slashCommand, setInput]`
- `useSlashCommand` 返回的对象未 memo，每次渲染都是新引用
- `lastAction` 状态从不清除
- 结果：`useEffect` 每次渲染都执行 → action 被无限重复消费 → `aiAssistant.clearChat()` 等被无限调用 → OOM

**修复方案**：
用 `useRef<number | null>` 跟踪已消费的 timestamp，跳过已处理的 action：

```typescript
const consumedTimestampRef = useRef<number | null>(null);

useEffect(() => {
  if (!slashCommand.lastAction) return;
  const { action, data, timestamp } = slashCommand.lastAction;
  // 跳过已消费的 action（防止无限循环）
  if (consumedTimestampRef.current === timestamp) return;
  consumedTimestampRef.current = timestamp;
  // ... switch(action) 执行
}, [slashCommand, setInput]);
```

## 三、关键技术点

### 1. 浏览器 E2E vs RTL 集成测试

| 维度 | 浏览器 E2E (subagent) | RTL 集成测试 |
|------|----------------------|-------------|
| 可靠性 | 低（3次测试3种结果，含幻觉） | 高（22/22 通过） |
| React 合成事件 | 触发不稳定 | `fireEvent` 原生支持 |
| CI 可运行 | 否 | 是 |
| 调试难度 | 高（黑盒） | 低（栈追踪清晰） |
| 适用场景 | 视觉/布局验证 | 组件集成逻辑验证 |

**决策**：对 React 组件集成验证，优先用 RTL 集成测试，浏览器 E2E 仅用于视觉/布局验证。

### 2. `vi.mock` 路径解析陷阱

`vi.mock('path')` 的路径是相对于**测试文件**解析的，不是相对于被测源文件。

错误示例（测试文件在 `ai-assistant/`，源文件 `useChatInput` 在 `ai-assistant/hooks/`）：
```typescript
// 错误：按源文件路径算
vi.mock('../../../../shared/services/AIAssistantService');
// 正确：按测试文件路径算
vi.mock('../../../shared/services/AIAssistantService');
```

### 3. `vi.hoisted` 模式

`vi.mock` 工厂函数被提升到文件顶部，不能引用外部变量。需要用 `vi.hoisted()` 包装：

```typescript
const { aiAssistantMock } = vi.hoisted(() => {
  const aiAssistantMock = { clearChat: vi.fn() /* ... */ };
  return { aiAssistantMock };
});

vi.mock('path/to/AIAssistantService', () => ({ aiAssistant: aiAssistantMock }));
```

### 4. useEffect 无限循环的检测模式

**症状**：测试运行时 V8 heap OOM。
**根因模式**：
- useEffect 依赖项包含每次渲染都是新引用的对象
- effect 内部触发状态更新（setInput）→ 重新渲染 → 新依赖引用 → effect 重新执行
- 配合未清除的状态（lastAction）形成无限循环

**修复模式**：用 `useRef` 跟踪已处理标记（timestamp/id），幂等跳过已处理项。
