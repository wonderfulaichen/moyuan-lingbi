## 二、关键决策（基于调研自主决策）

### 决策 1：purple/violet 合并
**选择**：合并为单一 primary 色阶

**理由**：
- `--color-primary-*`（50-600）已在 index.css 的 @theme 块中定义，各主题（朱砂红/翡翠绿/紫罗兰等）会覆盖这些变量
- purple 与 violet 在项目中语义同源，均作为主题强调色使用
- 合并后 `text-purple-300` → `text-[var(--color-primary-300)]`，随主题切换

**特殊处理**：
- `purple-700/900` 未在 @theme 中定义色阶
- `border-purple-900/10` 被滥用为通用边框 → 映射到 `var(--color-border-default)`（中性边框语义）
- `hover:from-purple-700` → `hover:from-[var(--color-primary-600)]`（用 600 替代 700 作为 hover 加深）

### 决策 2：StepWorld 业务色保留
**选择**：保留内联 hex 业务标识色（地点绿 #34d399、势力橙 #f59e0b、规则青 #22d3ee）

**理由**：与阶段 1+2 的业务色策略一致——业务标识色跨主题保持固定，是用户识别对象的"恒定标识"。

### 决策 3：装饰色保留
**选择**：保留 SettingsModal 中各功能板块的图标渐变

**保留清单**：
- 快速上手板块：amber/orange 渐变
- 数据管理板块：emerald/green 渐变
- 支持的提供商板块：blue/cyan 渐变
- UI 缩放板块：cyan/teal 渐变
- 效果预览板块：amber/orange 渐变

**例外**：主题外观板块图标原用 purple/violet（属主题色），已替换为 `var(--color-primary-*)`

### 决策 4：@theme 不额外扩展
**选择**：不扩展 @theme 块

**理由**：`--color-primary-*`（50-600）已足够覆盖需求；700/900 按语义重新映射（通用边框 → border-default，hover 加深 → primary-600），无需新增色阶。

## 五、踩坑记录

### 5.1 subagent 误用未定义变量
**现象**：subagent 在 L1586 将 `hover:to-violet-700` 替换为 `hover:to-[var(--color-primary-700)]`，但 `--color-primary-700` 未在 @theme 中定义（只有 50-600）。

**修复**：主流程检测到后立即修正为 `hover:to-[var(--color-primary-600)]`。

**经验**：subagent 执行替换时可能按字面映射（purple-700 → primary-700），需主流程验证变量是否存在。

### 5.2 PowerShell heredoc 不支持
**现象**：`git commit -m "$(cat <<'EOF'...EOF)"` 在 PowerShell 中报错。

**修复**：改用临时文件 + `git commit -F` 传递 commit message。

**经验**：Windows 环境下避免使用 bash heredoc 语法。
