## 二、关键决策（来自 AskUserQuestion 用户确认）

### 决策 1：执行范围

**未做**：阶段 3（SettingsModal.tsx 374 处、StepWorld.tsx 93 处）留待后续迭代。

### 决策 2：业务色策略
**选择**：业务色保持固定不随主题变

**应用范围**：
- 关系色（family/friend/romance/enemy/ally/neutral/master/disciple/other/involved）→ 固定 hex
- 角色色（主角/女主/反派/反派配角/配角）→ 固定 hex
- 文件夹类型色（world/characters/timeline/outline/detailed_outline/chapters/custom）→ 固定 Tailwind 类
- 时间轴节点圆点色数组 → 固定 hex（图表标识色）

**理论依据**：业务语义色是用户识别对象的"恒定标识"，跨主题切换会导致认知负担；状态色（success/warning/error）才是需要随主题适配的。

### 决策 3：Fallback 处理
**选择**：去除 hex fallback

**前提**：所有引用的 CSS 变量均已在 index.css 的 `:root` 和 `[data-theme-mode="dark"]` 中定义，确认无运行时 undefined 风险。

## 三、阶段 1：基础设施补齐

### 3.1 新增语义状态变量（index.css）

**问题**：原 CSS 变量系统缺乏统一的 success/warning/error/info/neutral 语义层，组件各自使用 `text-red-400`/`text-yellow-600` 等原生 Tailwind 类，主题切换失效。

**方案**：在 `:root` 末尾新增 15 个浅色变量，在 `[data-theme-mode="dark"]` 末尾新增 15 个暗色覆盖变量。

```css
/* 浅色模式 */
--color-success: #16a34a;
--color-success-bg: #f0fdf4;
--color-success-border: #bbf7d0;
--color-warning: #d97706;
--color-warning-bg: #fffbeb;
--color-warning-border: #fde68a;
--color-error: #dc2626;
--color-error-bg: #fef2f2;
--color-error-border: #fecaca;
--color-info: #2563eb;
--color-info-bg: #eff6ff;
--color-info-border: #bfdbfe;
--color-neutral: #4b5563;
--color-neutral-bg: #f9fafb;
--color-neutral-border: #e5e7eb;
```

暗色模式使用 rgba 半透明覆盖（如 `rgba(74, 222, 128, 0.1)` 作为 success-bg），保证与深色背景的视觉协调。

### 3.2 公共常量模块抽离

| 模块 | 路径 | 替代了什么 |
|---|---|---|
| `relationshipColors.ts` | `src/renderer/shared/constants/` | NetworkNodeDetails.tsx + MemoryNetworkView.tsx 各自的 RELATIONSHIP_COLORS/LABELS 重复定义 |
| `roleColors.ts` | `src/renderer/shared/constants/` | CharacterGraphView.tsx 的本地 ROLE_COLORS/getRoleColor |
| `folderColors.ts` | `src/renderer/features/settings/` | BubbleFolder.tsx + BubbleFolderContent.tsx 的 7 个文件夹类型映射（TYPE_LABELS/TYPE_ICONS/FOLDER_ICON_COLORS/FOLDER_BG_GRADIENTS/FOLDER_BG_COLORS/FOLDER_BORDER_COLORS/FOLDER_GLOW_COLORS） |

**工具函数**：每个模块都导出 `getXxxColor(type)` / `getXxxLabel(type)` 形式的安全访问器，避免运行时 undefined。

## 五、踩坑记录

### 5.1 并发 Edit 工具的竞争条件

**现象**：在同一消息中并发调用 6+ 个 `Edit` 工具（同一文件，不同 old_string），工具返回"successfully replaced"，但 PowerShell 验证发现实际未生效（只有最后一个 Edit 生效）。

**修复**：改为串行执行（一个 Edit 完成后再发下一个）。

**经验**：同一文件的多个 Edit 必须串行，不能用并行调用批量修改。

### 5.2 JSDoc 注释中 `*/` 被误解析

**现象**：folderColors.ts 构建报错 `Unexpected "*"`，指向 line 55 注释。

**根因**：注释 `/** ... from-*/to-* ... */` 中的 `*/to` 被解析器识别为注释结束符 `*/`，导致后续代码解析失败。

**修复**：将 `from-*/to-*` 改写为 `from-x 到 to-x`（2 处）。

**经验**：JSDoc 注释中避免使用 `xxx-*/yyy-*` 这类模式，esbuild 会误判。

## 七、防回退机制（轻量脚本 + pre-commit hook）

为保护阶段 1+2 的修复成果不被回退，在阶段 3 未启动前先建立防回退屏障。

### 7.1 设计决策

**方案选择**：轻量 Node 脚本 + git native pre-commit hook（无 husky 依赖）

**关键设计**：
- `--staged` 模式只检测 git diff 中的 **+ 行**（新增行），不检测已有代码
- 这是真正的"防回退"——阻止新增硬编码，不强制清理历史代码
- 全量模式（`npm run lint:colors`）检测整文件，用于主动审计

### 7.2 文件清单

| 文件 | 作用 |
|---|---|
| `scripts/check-tailwind-colors.mjs` | 主检测脚本（147 行），支持全量/`--staged` 双模式 |
| `scripts/install-hook.mjs` | 一键安装 git pre-commit hook |
| `.git/hooks/pre-commit` | 自动生成的 hook（运行 `npm run setup:hooks` 后生成） |

### 7.3 npm scripts

```json
"lint:colors": "node scripts/check-tailwind-colors.mjs",
"lint:colors:staged": "node scripts/check-tailwind-colors.mjs --staged",
"setup:hooks": "node scripts/install-hook.mjs"
```

### 7.4 检测规则

正则匹配 Tailwind 原生色阶类：
```
\b(text|bg|border|from|to|via|shadow|ring)-(red|green|blue|yellow|amber|emerald|teal|cyan|sky|indigo|violet|purple|fuchsia|pink|rose|gray|slate|zinc|neutral|stone|orange|lime)-\d{2,3}\b
```

**不匹配**：`text-[var(--color-xxx)]`、`text-primary`、`text-red-DEFAULT` 等（无数字后缀）。

### 7.5 豁免策略

| 类型 | 文件 | 策略 |
|---|---|---|
| 阶段3 待处理 | `SettingsModal.tsx`, `StepWorld.tsx` | 全量扫描时豁免；`--staged` 模式仍检测新增行 |
| 业务色常量模块 | `folderColors.ts` | 完全豁免（合法使用 Tailwind 类字符串） |

### 7.6 验证结果

| 测试场景 | 结果 |
|---|---|
| 全量扫描 | ✅ 发现 261 处已有硬编码（20+ 文件），PHASE3_PENDING 豁免生效 |
| staged 空暂存区 | ✅ 正常通过（exit 0） |
| staged 新增硬编码 | ✅ 精确检测到 `text-red-400`，定位 L13:42 |
| 端到端 git commit | ✅ hook 自动触发，未发现硬编码时提交成功 |

### 7.7 使用方式

```bash
# 首次安装 hook（项目新克隆后执行一次）
npm run setup:hooks

# 主动审计（检测全部已有硬编码）
npm run lint:colors

# 紧急跳过 hook
git commit --no-verify -m "..."
```
