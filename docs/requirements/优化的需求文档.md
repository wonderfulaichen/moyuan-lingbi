## 需求 1：内容设定 AI 生成集成全局悬浮窗

### 当前问题

在"内容设定"（世界构建）页面中，点击"AI生成"按钮后，底层调用了 `aiService.generate()` 方法进行 AI 内容生成，但**全局悬浮窗（`FloatingTaskOverlay`）没有出现**。用户无法感知生成进度、Token 消耗和完成状态，体验割裂。

### 根因分析

1. **悬浮窗触发机制**：`FloatingTaskOverlay` 的显示受控于 [`AIStatusContext`](src/renderer/shared/contexts/AIStatusContext.tsx) 的 `isGenerating` 状态。只有当组件调用 `setGenerating()` 后，悬浮窗才会出现。
2. **StepWorld 的实现缺陷**：[`StepWorld.tsx`](src/renderer/features/world/StepWorld.tsx:249) 的 `handleAIGenerate` 方法直接调用了 `aiService.generate()`，**完全没有使用 `AIStatusContext`** 提供的方法（`setGenerating`、`setTokenUsage`、`setComplete`、`setError`）。
3. **对比 StepInspiration**：[`StepInspiration.tsx`](src/renderer/features/inspiration/StepInspiration.tsx:108) 的正确实现通过 `inspirationService.ts` 中的 `generateSchemesStreaming()` 的回调函数（`onToken`、`onComplete`、`onTokenUsage`、`onError`）正确集成了 AIStatusContext，因此悬浮窗能正常显示。

### 修复方案

**目标**：使 `StepWorld` 的 AI 生成流程与全局 AI 状态上下文对接，确保悬浮窗正确弹出并展示进度/Tokens/完成状态。

#### 具体步骤

1. **导入 `useAIStatus` Hook**
   - 在 [`StepWorld.tsx`](src/renderer/features/world/StepWorld.tsx:1) 中添加：
     ```ts
     import { useAIStatus } from '../../shared/contexts/AIStatusContext';
     ```

2. **在组件内部获取 Context 方法**
   - 在 `StepWorld` 函数组件中添加：
     ```ts
     const { setGenerating, setTokenUsage, setComplete, setError } = useAIStatus();
     ```

3. **改造 `handleAIGenerate` 方法**
   - 在调用 `aiService.generate()` **之前**调用 `setGenerating()`，传入模型名称和任务描述
   - 在 `response` 返回后，如果有 `response.tokens`，调用 `setTokenUsage()`
   - 成功完成时调用 `setComplete()`
   - 捕获异常时调用 `setError()`
   - 最终无论成功失败，都调用 `setIsGenerating(null)` 恢复本地加载状态

4. **异常处理完善**
   - 当前 `try-finally` 块中没有 `catch`，需要补充完整的 try-catch 逻辑
   - 网络错误、JSON 解析错误等都应通过 `setError()` 上报

### 代码修改要点

| 文件 | 修改内容 |
|------|---------|
| `StepWorld.tsx` | 添加 `useAIStatus` import |
| `StepWorld.tsx` | 解构 `{ setGenerating, setTokenUsage, setComplete, setError }` |
| `StepWorld.tsx` | 在 `try` 块开头调用 `setGenerating()` |
| `StepWorld.tsx` | 成功后调用 `setTokenUsage()` + `setComplete()` |
| `StepWorld.tsx` | 补充 `catch` 块调用 `setError()` |
| `StepWorld.tsx` | `finally` 中保留 `setIsGenerating(null)` |

## 需求 2：参考 B 站视频设计元素优化产品 UI/UX

### 背景

参考 [B站视频 BV1f4w3znEKp](https://www.bilibili.com/video/BV1f4w3znEKp/) 中的 AI 小说生成工具设计，分析其优秀设计元素并给出借鉴建议。

### 视频内容总结

该视频展示了一款 AI 小说创作工具，核心功能包括：

| 功能模块 | 具体能力 |
|---------|---------|
| **自动化情节生成** | 主题/关键词输入 → 自动生成故事大纲、章节安排、情节转折点；支持故事类型（科幻/言情/悬疑）和风格（轻松/暗黑）参数定制 |
| **角色深度塑造** | 多维角色档案（性格/背景/人际关系）；AI 生成对话保持人物一致性；模拟角色情境反应 |
| **世界构建辅助** | 自动生成世界观（魔法体系/历史背景/地理结构）；环境细节描写（气候/建筑/文化习俗） |
| **交互式创作** | 边写边改、多续写选项、关键词联想、情节树扩展、随机事件/金句/伏笔生成 |
| **协作写作** | 多人协作 + AI 整合思路；可设置 AI 参与度（全自动/辅助建议） |
| **个性化 & 效率** | 基于大量小说数据集训练；用户可上传参考文本模仿风格；快速初稿 → 人工润色工作流 |

### 设计元素分析及借鉴建议

#### 1. 自动化情节生成：参数化配置面板

**视频中的设计**：用户通过一组结构化参数（故事类型下拉框 + 风格滑块/单选）快速定制生成方向，AI 输出完整大纲。

**可借鉴性：★★★★★（高优先级）**

**当前产品差距**：[`StepInspiration.tsx`](src/renderer/features/inspiration/StepInspiration.tsx:165) 的 `handleGenerateSchemes` 已实现了灵感/方案生成，但缺少**结构化参数面板**——用户只能通过文本 prompt 描述需求，没有可视化的故事类型/风格选择器。

**实现建议**：
- 在 [`StepInspiration.tsx`](src/renderer/features/inspiration/StepInspiration.tsx:738) 的 `renderSchemesPhase` 上方添加参数面板：
  ```tsx
  // 故事类型选择器（标签组）
  <div className="flex gap-2 flex-wrap mb-4">
    {['玄幻', '科幻', '言情', '悬疑', '都市', '历史'].map(g => (
      <button key={g} onClick={() => setGenre(g)}
        className={`px-3 py-1.5 rounded-full text-xs transition-all ${
          selectedGenre === g ? 'bg-primary-400/20 text-primary-300 border border-primary-500/30' : ''
        }`}
      >{g}</button>
    ))}
  </div>
  // 风格滑块
  <input type="range" min="0" max="100" value={styleValue}
    onChange={e => setStyleValue(+e.target.value)} />
  ```

## 需求 3（衍生）：修复 StepWorld 中的 CSS 变量问题

### 当前问题

在 [`StepWorld.tsx`](src/renderer/features/world/StepWorld.tsx:382) 中，标签徽章的样式使用了不存在的 CSS 变量 `var(--color-bg-overlay)`：

```tsx
style={{ color: 'var(--color-text-tertiary)', backgroundColor: 'var(--color-bg-overlay, rgba(0,0,0,0.2))' }}
```

该变量在 `index.css` 中未定义，且后备值为 `rgba(0,0,0,0.2)`——在**白天模式**下背景本身较亮，黑色叠加层会显示为灰暗色块，视觉上不协调。

### 修复方案

将 `var(--color-bg-overlay)` 替换为已正确定义且适配双模式的 `var(--color-surface-muted)`：

```tsx
style={{ color: 'var(--color-text-tertiary)', backgroundColor: 'var(--color-surface-muted)' }}
```

（参考 [`FloatingTaskOverlay.tsx`](src/renderer/shared/components/FloatingTaskOverlay.tsx) 的修复模式）
