## 2. 项目简介、核心价值与竞品差异

- **一句话简介**：墨渊灵笔是一款基于 AI 辅助的小说创作工坊，提供 GUI + Agent 双模式，帮助作者从灵感萌发到完成整部小说。
- **无后端**：纯本地应用（Electron 桌面端 + Capacitor Android 端），数据全部存储本地，无云端 / 外部数据库依赖。
- **源码规模**：204 个 `.ts` / `.tsx` 文件。

**核心价值（双引擎）**
- **GUI 是护城河**：三栏可视化创作界面（左文件树 / 中对话 / 右图示概览），可拖拽、可收起，把 AI 创作「看得见、可干预、能回退」——这是纯对话式竞品难以低成本复制的体验壁垒。
- **Agent 是攻城锤**：基于 DAG 调度引擎的 Agent 流水线（Writer / Auditor / Revisor 主链路 + Planner / Researcher / Memory 子 Agent），配合 Skill 系统、StepMemory、记忆银行，实现从灵感、大纲、角色、剧情到成稿的多 Agent 协同，而非单轮问答。

**竞品差异（概览，非逐一比对）**
- 市面多数 AI 写作工具停留在「对话框 + 提示词」形态；本项目的差异在于把创作流程工程化（Agent 编排 + 步骤记忆 + 记忆银行 + 可视化关系图），并兼顾本地模型离线可用。
- 具体竞品名称、功能矩阵与定价对比「待确认」（交接时未纳入审计范围，如需可后续补竞品调研章节）。

## 4. 快速上手

> 以下命令均假设已在项目根目录。未提交改动（脏工作区）见第 9 节，首次运行前请先评估是否影响启动。

**1) 安装依赖**
```bash
nvm use 22          # 或确保当前 Node >= 22
npm install
```

**2) 启动开发（仅前端 HMR）**
```bash
npm run dev          # 启动 Vite 开发服务器（前端热更新）
```

**3) 启动开发（Electron 桌面端，含主进程）**
```bash
npm run electron:dev # 先 build:electron，再 concurrently 起 vite + wait-on localhost:5180 后 electron .
```

**4) 构建（各平台）**

| 目标 | 命令 |
|---|---|
| 仅前端构建 | `npm run build`（`vite build`） |
| 桌面端构建（不打包） | `npm run electron:build`（`build` + `build:electron`） |
| 桌面端打包 Windows | `npm run electron:build-win` |
| 桌面端打包 macOS | `npm run electron:build-mac` |
| 桌面端打包 Linux | `npm run electron:build-linux` |
| Android 调试构建 | `npm run build:android`（`vite build` && `npx cap sync android`） |
| Android Release 构建 | `npm run build:android:release`（上一步 + `cd android && gradlew assembleRelease`） |
| PWA 构建 | `npm run build:pwa`（`vite build`） |

> 说明：`build:electron` 负责把 `src/main/main.js` 与 `preload.js` 复制到 `build/main/`；`preview` 为 `vite preview`；`electron:dev` 依赖 `localhost:5180`（与 `wait-on` 端口一致，若改动需同步）。

**5) 运行测试**
```bash
npm run test:run        # 单次运行（推荐交接验证用）
npm test                # 持续 watch 模式
npm run test:coverage   # 带覆盖率
```
- 当前实测结果：**209 passed / 2 failed（共 211，16 个 test files）**，详见第 8 节。

### 5.2 核心服务层（`src/renderer/shared/services/`）

| 模块 | 关键文件 | 职责 |
|---|---|---|
| **agent-runtime/** | `AgentRuntime`（DAG 调度引擎）、`AgentRegistry`（单例，注册 10 个 Agent）、`types.ts`、`internal/`（DependencyResolver、CancellationToken、StepRunner、mapper）、`agents/`（WriterAgent、AuditorAgent、RevisorAgent、PlannerAgent、ResearcherAgent、MemoryAgent + 各自 `.test.ts`） | Agent 流水线的调度与执行核心。 |
| **ai-assistant/** | `index.ts`（emit 去抖持久化 + 创作助手自动路由）、`processWithAI.ts`（迭代循环 / 流式 / tool call）、`UnifiedExecutor.ts`、`systemPrompt.ts`（5 子 Agent 的 AIAgent 定义）、`PlanExecutor.ts`、`ToolParser.ts`、`contextCompress.ts`、`contextBuilder.ts`、`detectAgentState.ts`、`TodoList.ts` | 创作助手的对话与自动路由引擎，子 Agent 按需自动触发（非手动）。 |
| **skill-registry/** | `index.ts`（SkillRegistry 单例）、`types.ts`、`skills/`（tokenSaver / contextCompress / consistencyCheck）+ `index.test.ts` | 内置 3 个 Skill，经 `invoke_skill` tool call 调用。 |
| **step-memory/** | `StepMemoryService.ts`（两级缓存：内存 + StorageProvider）、`types.ts`、`index.ts` | 步骤记忆体，支持依赖管理与 Fragment。 |
| **memory-bank/** | `MemoryBankService.ts`、`MemoryMaintenanceAgent.ts`、`MemoryNetworkService.ts`、`MemoryHealthService.ts`、`MemorySearchService.ts`、`MemoryVersionControl.ts`（含 `.test.ts`） | 记忆银行：网络关系图、健康度、检索、版本控制。 |
| **storage/** | `StorageProvider.ts`、`ElectronStorageProvider.ts`、`IndexedDBStorageProvider.ts`、`storage.ts` | 本地存储抽象与实现。 |
| **顶层服务** | `DataService.ts`（观察者模式 subscribe/emit/getFS，中央状态）、`AITaskManager.ts`、`ConsistencyService.ts`、`LocalModelService.ts`、`WhiteNoiseService.ts`、`InspirationService.ts`、`WellnessService.ts`、`MigrationService.ts`、`ProjectContextBuilder.ts`、`AIAssistantService.ts`、`ModelRouter.ts`、`aiService.ts` | 应用级编排与领域服务。 |

### 5.3 关键协作关系

- **DataService（中枢）**：以观察者模式对外提供 `subscribe` / `emit` / `getFS`，是中央状态与持久化入口。注意 `getFS` / `getData` 返回可变引用是已知技术债（P0-1，见第 10 节）。
- **Agent 流水线**：`AgentRegistry` 注册 10 个 Agent；`AgentRuntime` 用 DAG 调度；Writer / Auditor / Revisor 为主链路，Planner / Researcher / Memory 为子 Agent，由「创作助手」（`ai-assistant/index.ts`）按需自动路由，不依赖人工选择。
- **Skill 系统**：3 个内置 Skill 通过 `invoke_skill` tool call 被 Agent 调用，用于省 token / 上下文压缩 / 一致性检查。
- **StepMemory ↔ Agent**：步骤记忆体承载 Agent 间的中间产物（Fragment），支持依赖管理。
- **Memory Bank**：独立维护长期记忆网络、健康度、检索与版本控制，与 StepMemory 分工（短期步骤态 vs 长期知识）。
- **本地模型**：`LocalModelService` + `node-llama-cpp` 提供离线 LLM 推理，`ModelRouter` 负责云端 / 本地路由。

## 6. 配置与密钥交接（重点）

| 项 | 说明 | 风险 |
|---|---|---|
| **LLM API Key** | **无 `.env`**。Key 通过应用内 Settings 界面配置：`features/settings/StepSettings.tsx`、`SettingsModal.tsx`、`ModelRoutingPanel.tsx`，经 `DataService` 持久化到本地存储。 | 新接手人首次运行需在应用设置里填入**自己的** LLM 服务商 Key。切勿把 Key 写进代码 / 提交仓库。 |

| **外部服务** | 无外部数据库 / 云服务依赖，数据全部本地。 | 无。 |

> 交接动作：LLM Key 由接手人自行配置；Android 签名 alias / 密码需与原持有者线下移交并单独记录（不在本仓库、不在本文档留存明文）。
