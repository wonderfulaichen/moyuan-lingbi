## 二、关键技术决策与实现

### 2.1 P1-5：输入栏模型选择器

**问题**：右侧 AI 助手面板只显示当前模型名称，用户需进入 Settings 才能切换模型。

**方案**：将底部信息栏的模型名称展示改为 `<select>` 下拉选择器。

**改动文件**：
- `src/renderer/app/App.tsx`：给 `AIAssistantPanel` 传入 `models`、`activeModelId`、`onSelectModel` props
- `src/renderer/app/app-shell/AIAssistantPanel.tsx`：扩展接口，底部信息栏用 `<select>` 替换原模型名称展示
- `src/renderer/app/mobile/MobileApp.tsx` + `RightDrawer.tsx`：移动端抽屉同步补齐新 props

**技术要点**：
- 通过 `dataService.setActiveModel(id)` 切换模型，复用现有 DataService 能力
- 移动端和桌面端同步改造，保证体验一致
- `select` 的 `max-w-[110px] truncate` 避免模型名过长导致布局溢出

### 2.2 P1-6：Agent 角色切换系统提示

**问题**：`AIAssistantService.switchAgent()` 切换 Agent 时无界面提示，用户不知情。

**方案**：在 `switchAgent()` 中，当 `activeAgentId` 实际变化后，调用 `addMessage()` 插入一条 `role: 'system'` 的提示消息。

**改动文件**：
- `src/renderer/shared/services/ai-assistant/index.ts`：修改 `switchAgent()` 方法
- `src/renderer/app/app-shell/ai-assistant/components/MessageBubble.tsx`：修复 `isSummaryMsg` 运算符优先级 bug

**技术要点**：
- 同角色切换无提示，避免刷屏
- 初始化加载持久化的 `activeAgentId` 不经过 `switchAgent()`，不会误插提示
- 删除自定义 Agent 回退到 `agent-general` 时会触发一次提示，符合预期
- `MessageBubble.tsx` 的 `isSummaryMsg` 原判断 `msg.role === 'system' && msg.content.startsWith('【对话已压缩') || msg.content.startsWith('【')` 有运算符优先级 bug，任何以 `【` 开头的消息都会走压缩摘要样式，已修复为 `msg.role === 'system' && msg.content.startsWith('【对话已压缩')`

### 2.3 P1-4：右侧面板职责统一

**问题**：App.tsx 右栏 `AIAssistantPanel` 与 `StepAgent.tsx` 内部 RightPanel 存在职责重叠。

**调研发现**：`StepAgent.tsx` 是孤立组件（未被任何文件 import），其对话区、Agent 选择器、AI 状态显示与 `AIAssistantPanel` 完全重复，独有的 FileTree 已被 `FileSidebar` 覆盖，图示 Tab 是未实现的静态 SVG 占位。

**方案**：直接删除 `StepAgent.tsx` 及空目录 `features/agent/`。

**技术要点**：
- 通过 Grep 全局确认 `StepAgent` 仅在自身文件中出现，无外部依赖
- 删除前确认独有能力（FileTree、图示 Tab）已被其他组件覆盖或无保留价值
- 消除潜在的"双右栏并存"设计风险

### 2.4 streamingContent RAF 节流

**问题**：`setStreamingContent` / `setStreamingThinking` 每个 token 都调用 `emit()`，而 `emit()` 做了三件高开销事：通知所有 listeners（React setState）、`saveCurrentConversation`、`persistConversations`（写 localStorage）。

**方案**：在 `AIAssistantService` 中引入 RAF（requestAnimationFrame）节流。

**改动文件**：`src/renderer/shared/services/ai-assistant/index.ts`

**技术要点**：
- 新增 `rafId: number | null` 字段
- 新增 `scheduleEmit()` 方法：用 RAF 节流，每帧最多触发一次 emit
- `setStreamingContent` / `setStreamingThinking` 改用 `scheduleEmit()`
- `emit()` 内部自动取消 pending RAF，避免冗余更新（数据已同步到 state，后续 emit 会带上最新值）
- `updateAgentState` 等低频调用仍走 `emit()`，不需要节流
- 性能提升：原每 token 触发一次 setState + localStorage 写入，现降至每帧一次（~60fps）

### 2.5 工具页字号等价写法统一

**问题**：5 个 Step 组件出现 16 种字号规格，存在"同字号不同写法"的碎片化问题。

**方案（保守版）**：只统一等价写法，零视觉影响。

**改动文件**：
- `src/renderer/features/inspiration/StepInspiration.tsx`：`text-[14px]`→`text-sm`、`text-[12px]`→`text-xs`
- `src/renderer/features/settings/StepSettings.tsx`：内联 `fontSize:'8px'`→`text-[8px]` class
- `src/renderer/features/plot/StepPlot.tsx`：内联 `fontSize:'8px'`→`text-[8px]` class

**不做的（降级 P2）**：
- 不统一 11px vs 12px 语义差异（会改变视觉）
- 不引入字号 token 系统（改动过大）
- 不动 CSS 硬编码（需逐个验证选择器优先级）

## 五、经验沉淀

### 5.1 关键教训

1. **孤立组件是潜在风险**：`StepAgent.tsx` 未被任何文件 import，却自带三栏布局，一旦接入会形成双右栏。应定期检查组件是否被实际使用。

2. **运算符优先级 bug 易被忽视**：`a && b || c` 会被解析为 `(a && b) || c`，`MessageBubble.tsx` 的 `isSummaryMsg` 判断因此误判所有以 `【` 开头的消息。代码审查时需注意逻辑运算符组合。

3. **RAF 节流是流式输出的标准解法**：高频 setState + localStorage 写入是性能杀手，RAF 节流能将频率降至每帧一次，且 `emit()` 内部取消 pending RAF 可避免数据不一致。

4. **保守重构优先**：工具页字号统一只做"零视觉影响"的等价写法统一，不碰深层语义差异，确保零风险。激进重构应放在专门批次处理。

### 5.2 后续建议

1. **P2 性能组**：code splitting（1.1MB JS 未拆分）、流式滚动动画、1366px 布局偏紧
2. **P2 UI 规范组**：引入字号 token 系统、统一 CSS 变量/硬编码、工具页字号深层统一
3. **P2 代码质量组**：nanoid 重复实现、Conversation 压缩丢数据、agentId 强制类型转换
4. **待确认项**：AIAssistantService 绕过 DataService、DependencyResolver 串行降级
